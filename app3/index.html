Section 01

Getting Started

La-Fierce Admin is a native Android application that connects to the La-Fierce REST API. An active internet connection is required at all times.

System Requirements

RequirementMinimumNotes
Android VersionAndroid 5.0 (API 21)Tested on API 21+
InternetWi-Fi or Mobile DataRequired for all API calls
ScreenAny phone sizeHandles orientation changes gracefully
Storage~5 MBApp install size

Installation

1

Obtain the APK

Install the app-debug.apk file provided by your administrator onto your Android device. Enable "Install from unknown sources" in your device settings if prompted.

2

Grant Permissions

The app requires INTERNET permission only. No camera, storage, or location access is needed. Accept the permission when prompted during first install.

3

Launch the App

Tap the La-Fierce Admin icon on your home screen or app drawer. The splash screen will appear briefly, then navigate you to the Login screen.

4

Sign In

Use your administrator credentials to log in. The app does not persist sessions you will be asked to log in each time you launch the app.

Network Warning

This application communicates over HTTP (cleartext traffic enabled). Use it only on trusted networks. Do not use on public Wi-Fi without a VPN.

Enter Username

Saving

Tap the orange Save button in the top bar to submit the form. The button changes to "Saving" and disables while the API request is in progress. On success, a toast confirms "Person added!" or "Person updated!", and the Editor closes returning the user to the refreshed Dashboard. On failure, the button re-enables and a toast shows the error code.

Discarding Changes

Tap the Back arrow button in the top bar to cancel without saving. The Dashboard is not refreshed and no API calls are made.

Scroll the Form

The form is scrollable. If the keyboard is visible, the layout adjusts automatically (adjustResize mode). Scroll down to see the Highlights section and the Add Highlight row.

Section 06

Search & Sort

The Dashboard provides real-time search filtering and multiple sort options to help you quickly find the right person, regardless of how large the dataset grows.

Search Bar

The search bar is located below the "SUCCESSFUL PEOPLE" heading at the top of the list panel. It searches instantly as you type (no need to press Enter or a search button).

The search is case-insensitive and matches against three fields:

  • Person name e.g., typing "mar" will match "Maria", "Marco", "Ramona"
  • Rejection story content matches text within the rejection HTML
  • Success story content matches text within the success HTML

Clearing the search field instantly restores the full list.

Sort Options

Below the search bar is a sort dropdown spinner. Select one of five options:

OptionBehavior
DefaultShows records in the order returned by the API (insertion/server order)
Name AAlphabetical ascending by name
Name ZAlphabetical descending by name
Active FirstActive people appear at the top, inactive at the bottom
Inactive FirstInactive people appear at the top, active at the bottom

Sort and search work together the list is first filtered by the search query, then sorted by the selected option. Changing either updates the list immediately.

Tip: Finding Inactive Records

Use the Inactive First sort option combined with an empty search to quickly review all inactive people at once before deciding to re-activate or delete them.

Section 07

Highlights

Highlights are tagged phrases extracted from a person's stories. They allow specific text segments to be marked and surfaced prominently in the detail panel, making key narrative moments easy to spot.

What Is a Highlight?

A highlight is a combination of two pieces of data:

  • Section either rejection or successful, indicating which story the phrase comes from
  • Phrase the specific text string that exists within that story
[rejection] overcame three years of rejection
[successful] now leads a team of 20 engineers

Adding a Highlight (in the Editor)

1

Write Your Story First

Fill in the Rejection Story or Success Story text fields. The phrase you want to highlight must already exist in the story text the app validates this before adding.

2

Select a Section

Use the Section spinner in the "Add highlight" row at the bottom of the form. Choose rejection if the phrase is from the rejection story, or successful if it is from the success story.

3

Type the Phrase

In the Phrase text field (next to the spinner), type the exact phrase you want to highlight. The match is case-insensitive "Overcame" will match "overcame".

4

Tap "+ Add"

Tap the orange + Add button. If the phrase is found in the selected story, the highlight is added to the list above and the phrase field clears. If not found, a toast error will appear: "Phrase not found in the [section] story text".

Removing a Highlight

In the highlights list within the editor, each row has an button on the right. Tap it to immediately remove that highlight from the list. Changes are only saved to the server when you tap Save.

Viewing Highlights

When you select a person in the Dashboard and the Detail Panel opens, the HIGHLIGHTS section appears at the bottom of the scrollable area (only if the person has at least one highlight). Each highlight is displayed with the section tag in orange and the phrase in orange-red text.

Highlights Are Loaded from the API

When editing an existing person, the highlights are fetched fresh from the API via GET /api/successstories/{id}. This ensures you always see the most up-to-date highlight list, even if it was modified by another admin session.

Status Toggle

Each person has a status of either active or inactive. The Toggle button on the Dashboard provides a one-tap way to flip this status without entering the full editor.

How to Toggle

1

Select a Person

Tap any person in the list. The detail panel will open showing the person's current status badge.

2

Tap "Toggle"

Tap the Toggle button in the action bar. The status bar shows "Updating".

3

Confirmation

The status bar updates to show the result: "[Name] active" or "[Name] inactive". The full people list reloads automatically, updating the status dot colors and the Active/Inactive badge counts in the top bar.

Changing Status in the Editor

Status can also be changed while editing a person. In the Person Editor, the STATUS dropdown spinner allows selecting either active or inactive. This is useful when you are already making other changes and want to update the status at the same time.

Section 09

Delete Person

The Delete feature permanently removes a person and all associated data (stories, highlights) from the server. This action cannot be undone.

How to Delete

1

Select a Person

Tap the person in the list you wish to delete. The detail panel will open.

2

Tap "Del"

Tap the red-bordered Del button in the action bar.

3

Confirm Deletion

A confirmation dialog appears: "Delete '[Name]'?" with two options: Delete (red/positive action) and Cancel. Tap Delete to confirm.

4

Completion

The status bar shows "Deleting" followed by "[Name] deleted." The detail panel collapses and the list reloads without the deleted person.

Permanent Action Cannot Be Undone

Deleting a person sends a DELETE request to the server. There is no recycle bin or recovery mechanism. Always double-check the selected person's name in the confirmation dialog before confirming.

Section 10

API Reference

La-Fierce Admin communicates with the REST backend. All requests use a 30-second timeout for connect, read, and write operations.

Base URL

All endpoints listed below are relative to the backend API base URL. The app uses Retrofit 2 with Gson for JSON serialization.

Endpoints

GET api/successstories Returns all people

Called on Dashboard load and after any data-modifying operation. Returns an array of PersonDto objects (may not include full highlight data in the list view).

GET api/successstories/{id} Get single person

Called when tapping a person in the list and when the Editor opens for editing. Returns full PersonDto including all highlights. Falls back to cached list data on network error.

POST api/successstories Create person

Triggered when saving a new person from the Editor. Sends a SavePersonRequest JSON body. Returns the created PersonDto on success.

PUT api/successstories/{id} Update person

Triggered when saving an existing person from the Editor. Sends the full updated SavePersonRequest including all highlights.

DELETE api/successstories/{id} Delete person

Triggered after the user confirms deletion. Returns an empty body on success.

PATCH api/successstories/{id}/status Toggle status

Triggered when tapping the Toggle button. Sends the new status as a JSON string in the request body (e.g., "active" or "inactive").

HTML Stripping

The API stores stories as HTML (with <p>, <br>, and other tags). The app strips all HTML tags using a regex before displaying stories in the detail panel or pre-filling the editor text fields. When saving, plain text is sent and the server wraps it in HTML.

Section 12

Troubleshooting

The most common issues encountered when using La-Fierce Admin, along with their causes and solutions.

"Error: " in the Status Bar

Network or Server Error

Cause: The device cannot reach the backend API, or the server returned a non-success HTTP code.
Fix: Check your internet connection. If connection is fine, the server may be temporarily down or restarting. Wait a few seconds and try again (e.g., navigate away and back, or restart the app).

"Invalid credentials. Access denied."

Wrong Username or Password

Cause: The entered credentials do not match the hardcoded admin credentials.
Fix: Ensure you type exactly fireDraGon (mixed case) and WarDeathFuryStrife. Check that Caps Lock is not engaged and no extra spaces were added. The password visibility toggle (eye icon) can help you verify what was typed.

"Phrase not found in the [section] story text"

Highlight Phrase Validation Failure

Cause: The phrase you typed does not appear in the story text for the selected section.
Fix: Make sure the phrase text is actually present in the story field. Check for typos or extra spaces. The match is case-insensitive but requires the phrase to exist as a substring. Also ensure you selected the correct section (rejection vs. successful).

"Select a person first"

Action Requires Selection

Cause: You tapped Edit, Toggle, or Del without first selecting a person from the list.
Fix: Tap a person row to select it (the detail panel will slide up and the row will show the orange accent bar), then tap the action button.

App Loads But List Is Empty

No Data Returned

Cause: The API returned an empty array, or there was a connection failure at load time.
Fix: Check the status bar at the bottom. If it shows an error message, it is a network issue verify connectivity. If it shows "0 records loaded", the database may genuinely be empty or filtered by search. Clear the search bar and check that no sort is hiding records.

Save Button Stays Disabled

Save Request Hung or Failed Silently

Cause: A network timeout or server error occurred while saving.
Fix: If the button shows "Saving" for more than 30 seconds, the request has likely timed out. The button will re-enable on a caught exception. If it does not, force-close the app (swipe up in Recents and remove it) and relaunch. Note: verify whether the record was actually saved before entering it again to avoid duplicates.

Orientation Change

Safe to Rotate on Dashboard

The Dashboard handles orientation and screen size changes gracefully. The Person Editor, however, does not declare these config changes rotating may cause the editor to restart and clear unsaved data. Save your work before rotating the device while in the editor.
